## Decisions Made

- **Two-step Supabase insert** — Insert order with `reference: 'TEMP'`, then update with the real CC-XXXX reference after the UUID is returned. Supabase generates the UUID on insert, so the reference cannot be pre-computed.
- **Fire-and-forget email** — `resend.emails.send()` called without `await`, errors caught with `.catch()`. Email failure must never block order success.
- **Server-side price re-fetch** — Cart items from formData carry only productId and quantity. Prices fetched fresh from DatoCMS in the Server Action. Client-sent totals are never trusted.
- **Zod optional fields pattern** — `z.string().optional().or(z.literal(''))` handles both undefined and empty string for phone/notes (HTML forms submit empty string, not undefined).
- **Plain React email template** — Used plain JSX with inline styles instead of react-email package. Resend accepts any React component — no extra dependency needed.

## User Setup Required

**External services require manual configuration before this plan's Server Action can function end-to-end:**

**Supabase** — Orders table must be created by running the SQL migration from the plan's `user_setup` block in Supabase SQL Editor:
- Creates `orders` table with UUID primary key, reference, customer fields, items (JSONB), total, status
- Creates indexes on customer_email and created_at
- Enables RLS with anonymous INSERT policy and service-role-only SELECT policy

**Resend** — Seller email notification requires:
- `RESEND_API_KEY` — from Resend Dashboard > API Keys
- `SELLER_EMAIL` — seller's email address for order notifications
- `RESEND_FROM_EMAIL` — verified sender email (or `onboarding@resend.dev` for testing)

If these are not set, the Server Action will log a warning and skip email. Orders will still be saved to Supabase.
